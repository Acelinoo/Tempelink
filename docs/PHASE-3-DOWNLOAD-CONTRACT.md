# TEMPELINK — PHASE 3 DOWNLOAD DELIVERY CONTRACT
**Standardized Media Delivery Specification**
**Version:** 3.0.0  
**Status:** Canonical Contract

---

## 1. Core Principles

A download request in Tempelink is only valid if and only if:
```
[ VALID SIGNED TOKEN ]
         +
[ UNEXPIRED TIMESTAMP ]
         +
[ VALID MEDIA URL PROTOCOL & SYNTAX ]
         +
[ VALIDATED SSRF-SAFE DESTINATION ]
         +
[ VERIFIED SUPPORTED MEDIA MIME TYPE ]
         +
[ SANITIZED, DETERMINISTIC FILENAME ]
```

**Zero Open Proxy Policy:**
The Tempelink download endpoint strictly refuses client-supplied target URLs. The media destination is determined exclusively by the cryptographically signed, server-issued HMAC token.

## 2. Token Specification & Payload Schema

### 2.1. Token Structure
A Tempelink download token consists of two Base64URL-encoded segments separated by a period:
```
{base64url(jsonPayload)}.{base64url(hmacSha256Signature)}
```

### 2.2. Strict Payload Schema
```typescript
interface DownloadTokenPayload {
  /** Canonical media identifier (e.g. "7572245459951963423") */
  mediaId: string;

  /** Capability identifier (e.g. "tt_7572245459951963423_standard") */
  capabilityId: string;

  /** Original platform source URL (e.g. "https://www.tiktok.com/@user/video/...") */
  sourceUrl: string;

  /** Authorized destination CDN stream URL (must be valid http/https) */
  targetUrl: string;

  /** Sanitized suggested filename (e.g. "tiktok_7572245459951963423_standard.mp4") */
  filename: string;

  /** Validated MIME type (e.g. "video/mp4", "audio/mpeg", "image/jpeg") */
  mimeType: string;

  /** Expiration timestamp in milliseconds (Unix epoch) */
  expiresAt: number;
}
```

### 2.3. Mandatory Verification Invariants
1. **Signature Integrity:** Evaluated via `crypto.timingSafeEqual()`. Any modified byte in payload or signature fails with `SSRF_BLOCKED` (HTTP 403).
2. **Schema Conformance:** All 7 payload fields must be non-empty, of the correct JavaScript type, and `targetUrl` must be a valid, parsable URL. Missing or malformed fields fail with `INVALID_URL` (HTTP 400).
3. **Temporal Validity:** `Date.now() <= payload.expiresAt`. Expired tokens fail with `MEDIA_URL_EXPIRED` (HTTP 410).
4. **Perimeter Re-Check:** Even with a valid signature, `validateUrlSafety(parsedTargetUrl)` must pass, blocking loopbacks, RFC 1918 subnets, cloud metadata, and non-standard ports.

## 3. Endpoints & Protocol Contract

### 3.1. API Route: `POST /api/media/download`
Used by modern web and mobile clients to obtain an authorized download descriptor.

#### Request Headers
```http
POST /api/media/download HTTP/1.1
Content-Type: application/json
X-Correlation-ID: [optional UUID]
```

#### Request Body
```json
{
  "mediaId": "7572245459951963423",
  "capabilityId": "tt_7572245459951963423_standard",
  "sourceUrl": "https://www.tiktok.com/@user/video/7572245459951963423",
  "downloadToken": "eyJtZWRpYUlkIjoidHQ...HMAC_SIGNATURE"
}
```

#### Success Response (`200 OK`)
```json
{
  "success": true,
  "data": {
    "downloadType": "direct_url",
    "downloadUrl": "https://v16m.tiktokcdn-us.com/stream/...",
    "filename": "tiktok_7572245459951963423_standard.mp4",
    "mimeType": "video/mp4",
    "expiresAt": "2026-09-21T14:30:00.000Z"
  }
}
```

### 3.2. Direct Browser Route: `GET /api/media/download?token={signedToken}`
Used for direct file downloading and browser triggering.

#### Success Response (`302 Found`)


## 4. Filename Security & Sanitization Rules

Filenames generated by the server must adhere to strict security constraints:
1. **No Path Traversal:** Sequences like `../`, `..\`, `/`, or `\` are stripped.
2. **No Header / CRLF Injection:** Characters `\r`, `\n`, `%0d`, `%0a` are eliminated.
3. **No Illegal Filesystem Characters:** Characters `[\x00-\x1f\x7f:*?"<>|]` are replaced with safe underscores.
4. **Length Bounding:** Base filename is truncated to a maximum of 80 characters prior to extension appending.
5. **Deterministic Naming:** Canonical template: `{platform}_{mediaId}_{capabilityVariant}.{extension}`.
6. **RFC 5987 / RFC 6266 Headers:** Format both ASCII fallback `filename="..."` and unicode-safe `filename*=UTF-8''...`.

---

## 5. Media Type Validation & Probing

Before delivering or redirecting media streams:
1. The token payload must declare a supported MIME type:
   - `video/mp4`
   - `video/webm`
   - `audio/mpeg`
   - `audio/mp4`
   - `image/jpeg`
   - `image/png`
   - `image/webp`
2. If upstream probing is enabled or executed, any response returning `Content-Type: text/html` or non-media content is rejected with `INVALID_URL` or `PROVIDER_UNAVAILABLE`, preventing HTML injection or masquerading phishing pages.

## 6. Error Codes & HTTP Status Mapping

| Error Code | HTTP Status | Indonesian User Message | Cause |
| :--- | :---: | :--- | :--- |
| `INVALID_URL` | 400 | Format token atau URL tidak valid. | Malformed token, schema validation failure, or bad URL syntax. |
| `SSRF_BLOCKED` | 403 | Akses ke alamat link ini diblokir demi alasan keamanan sistem. | Tampered signature, forged token, or private/metadata destination IP. |
| `CONTENT_UNAVAILABLE` | 404 | Media tidak ditemukan atau telah dihapus oleh platform. | Upstream provider reported content not found. |
| `DOWNLOAD_UNAVAILABLE`| 404 | Download token tidak ditemukan atau opsi unduhan tidak tersedia. | Request missing token or capability unavailable. |
| `MEDIA_URL_EXPIRED` | 410 | Tautan unduhan media telah kedaluwarsa. Silakan periksa kembali tautan Anda. | Token expired (`expiresAt < now`) or upstream CDN token invalid. |
| `RATE_LIMITED` | 429 | Permintaan terlalu banyak. Silakan tunggu beberapa saat. | Exceeded 10 download requests per minute. |
| `PROVIDER_UNAVAILABLE`| 503 | Layanan platform sedang mengalami gangguan. Silakan coba lagi nanti. | Upstream gateway 5xx error or connection drop. |
| `TEMPORARY_FAILURE` | 504 | Koneksi ke penyedia media melampaui batas waktu (timeout). | Upstream timeout exceeded. |
| `INTERNAL_ERROR` | 500 | Terjadi kesalahan pada sistem. Tim kami sedang menanganinya. | Unexpected server exception or missing production signing secret. |
